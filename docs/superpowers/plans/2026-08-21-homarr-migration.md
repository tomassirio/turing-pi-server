# Homarr Dashboard Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the stale `services/homerr` (Homer) chart with a self-authored `services/homarr` chart running the actively developed Homarr dashboard, with its one real secret managed through SOPS.

**Architecture:** A new Helm chart at `services/homarr`, structured like `services/picard` (the repo's newest reference chart: proper `app.kubernetes.io/*` labels, ServiceAccount, HPA stub) but using `services/radarr`'s more correct guarded `subPath` handling for the config volume. `appdata` (Homarr's SQLite DB) is a local `emptyDir`, mirrored to `nas-config-pvc` via the repo's existing `common.restore.initContainer` / `common.backup.sidecar` templates — the same anti-corruption pattern already used for every other stateful app in this repo. `SECRET_ENCRYPTION_KEY` lives in a new SOPS-encrypted `services/homarr/secrets.yaml`, decrypted the same way `services/qbittorrent/secrets.yaml` is (by the existing `.github/workflows/helm-deploy.yaml` SOPS step; done by hand here for local verification).

**Tech Stack:** Helm 3, SOPS 3.9 + age encryption, Kubernetes StatefulSet/Service/Ingress (nginx), `ghcr.io/homarr-labs/homarr` image.

## Global Constraints

- Chart name/dir: `homarr` (not `homerr`/`homer`) — from spec §"Chart".
- Image: `ghcr.io/homarr-labs/homarr`, tag `latest` — from spec §"Chart".
- Container port: `7575` — from spec §"Chart".
- Ingress host: `dashboard.localhome.com`, TLS secret `localhome-tls` — from spec §"Chart" (unchanged from Homer).
- No docker-socket mount — from spec §"Chart" / Non-goals.
- `appdata` persistence: local `emptyDir` + `common` backup/restore sidecars against `nas-config-pvc` subPath `homarr` — from spec §"Persistence".
- `SECRET_ENCRYPTION_KEY` generated via `openssl rand -hex 32`, stored SOPS-encrypted in `services/homarr/secrets.yaml` using the repo's existing age recipient (`age1jsd2g7m3vkh629cged87fvvetsuzv8dalkv38ykpqmyqrkpqmymsr62hqr`, from `.sops.yaml`) — from spec §"Secret".
- `services/homerr` deleted outright via `git rm -r` — from spec §"Removal".
- No entry added to `config/namespace-overrides.txt` (deploys to default namespace) — from spec §"Deployment".
- Board/tile/widget curation is explicitly out of scope for this plan (spec §"Board curation" — done later, interactively, via `claude-in-chrome`, not through git).
- Never leave a decrypted `secrets.dec.yaml` on disk or commit it — `.gitignore` already excludes `*secrets.dec.*`; every verification step that decrypts must delete the temp file immediately after.

### Task 2: SOPS-encrypted `SECRET_ENCRYPTION_KEY`

**Files:**
- Create: `services/homarr/secrets.yaml`
- Create: `services/homarr/templates/secret.yaml`

**Interfaces:**
- Consumes: `.sops.yaml`'s existing age recipient (`age1jsd2g7m3vkh629cged87fvvetsuzv8dalkv38ykpqmyqrkpqmymsr62hqr`); `homarr.fullname` / `homarr.labels` from Task 1.
- Produces: a Kubernetes `Secret` named `<release>-homarr-secret` with key `SECRET_ENCRYPTION_KEY`, consumed by Task 3's StatefulSet via `envFrom`.

- [ ] **Step 1: Generate the encryption key**

Run:
```bash
openssl rand -hex 32
```
Expected: a 64-character hex string. Copy it — it's used as `<KEY>` in Step 2.

- [ ] **Step 2: Write and encrypt `secrets.yaml`**

Create the plaintext content first, then encrypt in place. This mirrors the shape of `services/qbittorrent/secrets.yaml` (`secrets.<name>.data.<field>`), which is what `.sops.yaml`'s `encrypted_regex` (`^(data|stringData|token|username|password|email|game_password|crt|key|FTP_USER_PASS)$`) targets.

```bash
cat > services/homarr/secrets.yaml <<'EOF'
secrets:
    homarr:
        data:
            encryptionKey: <KEY>
EOF
sops --encrypt --in-place services/homarr/secrets.yaml
```
Expected: `services/homarr/secrets.yaml` now contains `sops:` metadata and `encryptionKey: ENC[AES256_GCM,...]` instead of the plaintext value.

- [ ] **Step 3: Verify decryption round-trips**

Run:
```bash
sops -d services/homarr/secrets.yaml | grep encryptionKey
```
Expected: `encryptionKey: <KEY>` — the exact 64-char hex string from Step 1, decrypted back to plaintext.

- [ ] **Step 4: Create `templates/secret.yaml`**

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: {{ include "homarr.fullname" . }}-secret
  labels:
    {{- include "homarr.labels" . | nindent 4 }}
type: Opaque

  SECRET_ENCRYPTION_KEY: {{ .Values.secrets.homarr.data.encryptionKey | quote }}
```

- [ ] **Step 5: Verify it renders with the decrypted value, then clean up**

Expected: output shows both `kind: Secret` and `SECRET_ENCRYPTION_KEY: "<KEY>"` matching Step 1's value. Confirm the `rm` ran — `ls services/homarr/*.dec.yaml` must report no such file.
